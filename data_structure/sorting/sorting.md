## 핵심 요약

- 정렬은 데이터를 순서대로 배치해 검색을 빠르게 만드는 작업이다. 주기억장소만으로 처리하면 내부 정렬, 용량을 넘겨 외부 저장장치를 쓰면 외부 정렬이다.
- 선택/버블/삽입은 모두 $O(n^2)$로 느리지만 구현이 단순하다. 삽입은 이미 정렬된 데이터에서는 $O(n)$으로 빠르고 안정 정렬이다.
- 퀵/힙/머지는 $O(nlog_2n)$급이다. 퀵은 평균이 가장 빠르지만 분할이 치우치면 최악 $O(n^2)$이고, 힙과 머지는 최악에도 $O(nlog_2n)$을 보장한다.
- 기수 정렬은 비교를 쓰지 않아 $O(dn)$이 가능하지만, 키가 같은 길이의 숫자나 단순 문자여야 한다는 제약이 있다.

## 1. 선택 정렬

### 1.1 정렬의 개념

데이터를 저장하는 목적은 나중에 다시 찾아 쓰기 위함이다. 입력된 순서 그대로 아무렇게나 쌓아두면 원하는 값을 찾는 데 시간이 오래 걸린다. 실제로 다루는 데이터는 수백\~수천 개가 아니라 수백만\~수억 개인 경우가 흔하므로, 이름순이나 번호순으로 미리 정리해두면 검색이 훨씬 수월해진다. 즉 정렬은 검색을 빠르게 하기 위한 사전 작업이다.

정렬은 작업이 이루어지는 장소에 따라 두 가지로 나뉜다.


| 구분                     | 조건                                                             | 해당 방법                         |
| -------------------------- | ------------------------------------------------------------------ | ----------------------------------- |
| 내부 정렬(internal sort) | 데이터 크기가 주기억장소 용량보다 작아 메모리 안에서 처리        | 버블, 삽입, 선택, 퀵, 쉘, 힙 정렬 |
| 외부 정렬(external sort) | 데이터 크기가 주기억장소 용량보다 커서 외부 저장장치를 함께 사용 | 머지(merge) 정렬                  |

### 1.2 선택 정렬의 개념

리스트를 왼쪽(정렬 완료)과 오른쪽(미정렬) 두 부분으로 나누어 생각한다. 시작할 때 왼쪽은 비어 있고 정렬할 숫자는 전부 오른쪽에 있다.

- 오른쪽에서 가장 작은 값을 골라 오른쪽의 첫 번째 자리와 맞바꾼다.
- 그러면 왼쪽 영역은 한 칸 늘고, 오른쪽 영역은 한 칸 줄어든다.
- 오른쪽이 완전히 비면 정렬이 끝난다.

예를 들어 `5 3 8 1 2 7`은 다음처럼 매 단계 최솟값을 앞으로 가져오며 정렬된다: 5<->1 교환, 3<->2 교환, 8<->3 교환, 5는 이미 제자리, 8<->7 교환 -> `1 2 3 5 7 8`.

### 1.3 선택 정렬 알고리즘

```
selection_sort(A, n)

for i←0 to n-2 do
        least ← A[i], A[i+1],..., A[n-1] 중에서 가장 작은 값의 인덱스;
        A[i]와 A[least]의 교환;
        i++;
```

```
#define SWAP(x, y, t) ( (t)=(x), (x)=(y), (y)=(t) )
void selection_sort(int list[], int n)
{       int i, j, least, temp;
        for(i=0; i<n-1; i++) {
                least = i;
                for(j=i+1; j<n; j++)                    // 최소값 탐색
                        if(list[j]<list[least]) least = j;
                SWAP(list[i], list[least], temp);
        }
}
```

### 1.4 선택 정렬의 성능 분석

- 비교 횟수: (n-1) + (n-2) + … + 1 = n(n-1)/2 = $O(n^2)$
- 이동 횟수: 3(n-1)
- 전체 시간 복잡도: $O(n^2)$
- 안정성을 만족하지 않음

## 2. 버블 정렬

### 2.1 버블 정렬의 개념

정렬이 진행되는 모습이 물속 거품(bubble)이 떠오르는 것과 닮아 붙은 이름이다. 이웃한 두 값을 계속 비교하며 자리를 바꿔 나간다.

- 1단계: `i = 0,1,…,n-2`에 대해 `list[i]`와 `list[i+1]`을 비교해 뒤 값이 더 작으면 교환한다. 한 바퀴 돌면 가장 큰 값이 맨 뒤로 밀려난다.
- 2단계: `i = 0,1,…,n-3` 범위로 같은 작업을 하면 두 번째로 큰 값이 뒤에서 두 번째 자리에 놓인다.
- 3단계: 범위를 `i = 0,1,…,n-4`로 줄여 세 번째로 큰 값을 자리 잡게 한다.
- …
- n-1단계: `i = 0`만 비교하면 남은 값이 제자리를 찾아 정렬이 끝난다.

매 단계 비교 범위가 하나씩 줄어드는 것이 핵심이다.

### 2.2 버블 정렬 알고리즘

각 단계에서 첨자가 어떻게 변하는지, 그리고 `if` 문에서 일어나는 비교 횟수는 다음과 같다.


| 단계    | 첨자 변화                      | 비교 횟수 |
| --------- | -------------------------------- | ----------- |
| 1단계   | i=n-1 : j=0,1,2,…,n-4,n-3,n-2 | (n-1)번   |
| 2단계   | i=n-2 : j=0,1,2,…,n-4,n-3     | (n-2)번   |
| 3단계   | i=n-3 : j=0,1,2,…,n-4         | (n-3)번   |
| …      | …                             | …        |
| n-2단계 | i=2 : j=1,0                    | 2번       |
| n-1단계 | i=1 : j=0                      | 1번       |

따라서 전체 비교 횟수는 T(n) = n(n-1)/2이고, 비교 기준 수행시간 복잡도는 $O(n(n-1)/2) = O(n^2)$이다. n에 대한 2차 함수만큼 시간이 든다.

`15 4 8 3 50 9 20`의 진행 과정:

```
/* list에 대한 기본 버블정렬 알고리즘 */
void bubble_sort(element list[], int n) {
    int i, j;
    element next;
    for(i = n-1; i > 0; i--) {          /*1*/
        for(j = 0; j < i; j++) {        /*2*/
            if(list[j] > list[j + 1]) {/*3*/
                SWAP(list[j], list[j + 1]);
            }
        }
    }
}
```

진행 과정: 시작 `15 4 8 3 50 9 20` -> 1단계 `4 8 3 15 9 20 50` -> 2단계 `4 3 8 9 15 20 50` -> 3단계 `3 4 8 9 15 20 50` -> 4단계 `3 4 8 9 15 20 50`. 매 단계 가장 큰 값이 뒤쪽에 확정된다.

### 2.3 버블 정렬의 성능 분석

- 비교 횟수: 최상, 평균, 최악 모든 경우가 동일하다.
- 이동 횟수:
  - 역순 정렬(최악): 이동 횟수 = 3 x 비교 횟수
  - 이미 정렬됨(최선): 이동 횟수 = 0
  - 평균: $O(n^2)$
- 레코드 이동이 지나치게 많다.
- 이동 연산은 비교 연산보다 시간이 더 많이 든다.

### 2.4 버블 정렬 알고리즘의 개선

한 단계에서 교환이 한 번도 일어나지 않았다면 이미 정렬이 끝난 상태이므로 다음 단계로 갈 필요가 없다. 이 사실을 `flag` 변수로 점검해 중간에 멈출 수 있다.

```
/* list에 대한 개선된 버블정렬 알고리즘 */
void bubble_sort(element list[], int n) {
    int i, j;
    int flag = 1;
    element next;
    for(i = n - 1; flag > 0; i--) {         /*1*/
        flag = 0;
        for(j = 0; j < i; j++) {            /*2*/
            if(list[j] > list[j + 1]) {
                SWAP(list[j], list[j + 1]);
                flag = 1;                   /*3*/
            }
        }
    }
}
```

## 3. 삽입 정렬

### 3.1 삽입 정렬의 개념

삽입 정렬은 `j = 1,…,n-1`에 대해 각 단계에서 `list[j]`를 앞쪽 값들과 차례로 비교하며 자리를 바꿔 넣는다. 더 작은 값을 만나면 멈춘다. `j`를 1, 2, 3…순으로 진행하므로 `j`번째 차례가 되면 앞쪽 j-1개는 이미 정렬이 끝난 상태이고, `list[j]`는 그 정렬된 구간 안에서 자기 자리를 찾아 들어가는 셈이다. 이때 `list[j]`보다 큰 값들은 한 칸씩 뒤로 밀려난다.

단계별로 보면:

- 1단계: `list[1]`을 `list[0]`과 비교해 더 작으면 앞으로 보낸다. -> `list[0..1]` 정렬됨.
- 2단계: `list[2]`를 `list[1], list[0]` 순으로 비교해 제자리에 끼운다. -> `list[0..2]` 정렬됨.
- 3단계: `list[3]`을 `list[2], list[1], list[0]` 순으로 비교한다. -> `list[0..3]` 정렬됨.
- …
- n-1단계: `list[n-1]`을 앞쪽 값들과 비교해 끼운다. -> 전체 정렬 완료.

진행 예시(n=5):

입력 `(5, 4, 3, 2, 1)` - 매 단계 새 값이 맨 앞까지 밀려 내려간다.


| i | [0] | [1] | [2] | [3] | [4] | 설명               |
| --- | ----- | ----- | ----- | ----- | ----- | -------------------- |
| - | 5   | 4   | 3   | 2   | 1   | 0단계: 초기 데이터 |
| 1 | 4   | 5   | 3   | 2   | 1   | 4를 앞으로 이동    |
| 2 | 3   | 4   | 5   | 2   | 1   | 3을 앞으로 이동    |
| 3 | 2   | 3   | 4   | 5   | 1   | 2를 앞으로 이동    |
| 4 | 1   | 2   | 3   | 4   | 5   | 1을 앞으로 이동    |

입력 `(3, 2, 5, 1, 4)` - 이미 큰 값이면 이동이 없다.


| i | [0] | [1] | [2] | [3] | [4] | 설명                        |
| --- | ----- | ----- | ----- | ----- | ----- | ----------------------------- |
| - | 3   | 2   | 5   | 1   | 4   | 0단계: 초기 데이터          |
| 1 | 2   | 3   | 5   | 1   | 4   | 3을 2와 비교, 앞으로 이동   |
| 2 | 2   | 3   | 5   | 1   | 4   | 5를 3과 비교, 이동 없음     |
| 3 | 1   | 2   | 3   | 5   | 4   | 1을 5,3,2 순으로 비교·이동 |
| 4 | 1   | 2   | 3   | 4   | 5   | 4를 5와 비교·이동          |

### 3.2 삽입 정렬의 예

`5 3 8 1 2 7`을 삽입해 나가면: 3 삽입 -> 8은 이미 제자리 -> 1 삽입 -> 2 삽입 -> 7 삽입 -> `1 2 3 5 7 8`. 삽입할 값을 임시로 빼두고, 그보다 큰 값들을 한 칸씩 뒤로 민 뒤 생긴 빈자리에 값을 넣는 방식이다.

### 3.3 삽입 정렬 알고리즘

```
/* 삽입정렬 - 데이터를 앞으로 이동하면서 끼워넣는다 */

void insertion_sort(element list[], int n) {
    int i, j;
    element next;
    for(i = 1; i < n; i++) {
        next = list[i];
        for(j = i - 1; j >= 0 && next.key < list[j].key ; j--)
            { list[j + 1] = list[j];};
        list[j + 1] = next;
    }
}
```

### 3.4 삽입 정렬의 성능 분석

첨자 변화와 비교 횟수(최대의 경우):


| 단계    | 첨자 변화                  | 비교 횟수(최대) |
| --------- | ---------------------------- | ----------------- |
| 1단계   | i=1 : j=0                  | 1번             |
| 2단계   | i=2 : j=1,0                | 2번             |
| 3단계   | i=3 : j=2,1,0              | 3번             |
| …      | …                         | …              |
| n-2단계 | i=n-2 : j=n-3,…,2,1,0     | n-2번           |
| n-1단계 | i=n-1 : j=n-2,n-3,…,2,1,0 | n-1번           |

각 단계는 비교 값보다 작은 값을 만나면 멈추므로 실제로는 더 적게 비교하지만, 최대를 가정하면 전체 비교 횟수 T(n) = n(n-1)/2이고 수행시간 복잡도는 O(n(n-1)/2) = O(n²)이다.

경우별 성능:

- 최선 $O(n)$: 이미 정렬된 경우 - 비교 n-1번
- 최악 $O(n^2)$: 역순 정렬된 경우 - 모든 단계에서 앞의 자료 전부 이동
  - 비교: $\sum$(i=1..n-1) i = n(n-1)/2 = $O(n^2)$
  - 이동: n(n-1)/2 + 2(n-1) = $O(n^2)$
- 평균 $O(n^2)$
- 이동이 많아 레코드가 크면 불리하다.
- 안정된 정렬 방법이다.
- 대부분 정렬되어 있으면 매우 효율적이다.

## 4. 퀵 정렬

### 4.1 퀵 정렬의 개념

평균적으로 가장 빠른 정렬 방법이며 분할 정복법을 쓴다. 리스트를 기준값을 중심으로 크기가 다른 두 부분리스트로 나누고, 각 부분리스트를 다시 퀵 정렬로 처리한다(재귀 호출).

동작 과정:

- 과정 1: 리스트에서 기준 데이터(pivot value)를 하나 정한다. 그다음 앞쪽에서는 기준보다 **큰 값**을, 뒤쪽에서는 기준보다 **작은 값**을 찾아 가운데로 좁혀 온다. 양쪽에서 옮길 값을 찾으면 서로 맞바꾼다. 이 과정이 끝나면 리스트는 자연스럽게 "기준보다 작은 값들"과 "기준보다 큰 값들" 두 덩어리로 갈라진다. 기준 데이터는 앞뒤 탐색이 서로 만나는 위치에 놓인다.
- 과정 2: 갈라진 두 리스트 각각에 대해 기준값을 새로 정하고 같은 분할을 반복한다. 계속 반복하면 결국 원소가 1개뿐인 리스트가 남고, 그 시점에 자동으로 정렬이 끝난다.

한 번 분할할 때마다 리스트 크기가 평균적으로 절반으로 줄어든다. 이렇게 문제를 더 작은 문제로 쪼개어 해결하는 방식을 분할-정복(divide and conquer)이라 한다.

예: `5 3 8 4 9 1 6 2 7`에서 5를 피벗으로 분할하면 `[1 3 2 4]` `5` `[9 6 8 7]`처럼 피벗보다 작은 값과 큰 값으로 나뉜다.

### 4.2 퀵 정렬의 예

입력 리스트 10개 `(26, 5, 37, 1, 61, 11, 59, 15, 48, 19)`, 각 단계의 기준값은 그 구간의 첫 번째 원소로 한다.


| R₀ | R₁ | R₂ | R₃ | R₄ | R₅ | R₆ | R₇ | R₈ | R₉ | left | right | 단계  |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ------ | ------- | ------- |
| 26  | 5   | 37  | 1   | 61  | 11  | 59  | 15  | 48  | 19  | 0    | 9     | 1단계 |
| 11  | 5   | 19  | 1   | 15  | 26  | 59  | 61  | 48  | 37  | 0    | 4     | 2단계 |
| 1   | 5   | 11  | 19  | 15  | 26  | 59  | 61  | 48  | 37  | 0    | 1     | 3단계 |
| 1   | 5   | 11  | 19  | 15  | 26  | 59  | 61  | 48  | 37  | 3    | 4     | 4단계 |
| 1   | 5   | 11  | 15  | 19  | 26  | 59  | 61  | 48  | 37  | 6    | 9     | 5단계 |
| 1   | 5   | 11  | 15  | 19  | 26  | 48  | 37  | 59  | 61  | 6    | 7     | 6단계 |
| 1   | 5   | 11  | 15  | 19  | 26  | 37  | 48  | 59  | 61  | 9    | 9     | 7단계 |
| 1   | 5   | 11  | 15  | 19  | 26  | 37  | 48  | 59  | 61  |      |       | 8단계 |

- 1단계: 기준값 26에서 19<->37, 61<->15가 바뀐다. 앞뒤 탐색이 만나는 중간 지점이 R5이므로 R5와 기준값 R1을 교환한다. 결과는 2단계 시작 상태가 된다.
- 5단계: 오른쪽 절반 리스트의 정렬을 시작한다.
- 8단계: 최종 결과다.

### 4.3 퀵 정렬 알고리즘

```
/* 퀵 정렬 프로그램 */
void quicksort(element list[], int left, int right)
{
    int pivot, i, j; element temp;
    if(left < right) {                          /* 분할 */
        i = left; j = right + 1;
        pivot = list[left].key;
        do {
            do     i++;
            while(list[i].key < pivot && i<=right);
            do     j--;
            while(list[j].key > pivot);
            if(i < j)
                        SWAP(list[i], list[j], temp);
        } while(i < j);
        SWAP(list[left], list[j], temp);
        quicksort(list, left, j - 1);
        quicksort(list, j + 1, right);
    }
}
```

### 4.4 퀵 정렬의 성능 분석

n개 데이터의 수행시간을 $T(n)$이라 하면, 첫 단계를 거치면 기준값을 중심으로 대략 n/2 크기의 리스트가 2개 생긴다. 이 두 리스트로 나누기 위해 n개에 대해 n번의 비교를 해야 한다. 즉 "n번 비교 + 절반 리스트 2개의 정렬시간"이므로:

```
T(n) ≤ c·n +  2·T(n/2)
     ≤ c·n + 2(c·n/2 + 2·T(n/4))
     ≤ 2·c·n + 4·T(n/4)
     ···
     ≤ c·n·log₂n + n·T(1) = O(n·log₂n)
```

- 데이터 크기 분포가 고르면(거의 균등 분할) 평균 수행시간은 $O(nlog_2n)$이고, 총 이동 횟수는 비교 횟수에 비해 적어 무시할 수 있다.
- 데이터 분포가 고르지 않으면(극도로 불균등 분할) 최악 $O(n^2)$이다. 예를 들어 이미 정렬된 리스트를 정렬할 때가 이에 해당하며, 이때도 이동 횟수는 무시할 수 있다.
- 중간값(median)을 피벗으로 고르면 불균등 분할을 완화할 수 있다.

## 5. 힙 정렬

### 5.1 힙(heap)의 개념

힙은 부모 노드의 값이 자식 노드의 값보다 항상 큰(또는 작은) 완전 이진 트리다. 부모가 더 큰 쪽을 Max Heap, 더 작은 쪽을 Min Heap이라 한다. Max Heap에서는 가장 큰 값이 루트에, 가장 작은 값은 리프 노드 중에 있다. 힙은 완전 이진 트리이므로 트리 구조지만 배열에 저장하는 편이 더 효율적이다.

/* 힙을 위한 자료구조 선언 */

#define MAX_ELEMENTS 200
#define HEAP_FULL(n) (n == MAX_ELEMENTS - 1)
#define HEAP_EMPTY(n) (!n)
typedef struct {
    int key;
    /* other field */
} element;
element heap[MAX_ELEMENTS];
int n = 0;
배열 저장 예(첨자 1부터 저장 가정): 트리 `20 / (15, 2) / (14, 10)`은 배열로 `[1]=20, [2]=15, [3]=2, [4]=14, [5]=10`처럼 담긴다.

### 5.2 힙의 노드 추가

새 노드를 힙에 삽입하는 과정(adjust 과정):

1. 새 노드의 위치를 정한다 - 마지막 레벨의 마지막 노드.
2. 삽입할 데이터를 새 노드에 놓는다.
3. 새 노드와 부모를 비교해 부모가 더 작으면 교환하는 과정을, 루트에 도달할 때까지 반복한다.

부모 노드의 위치는 `i/2`에 있고, 수행시간은 트리 높이와 같다. 따라서 새 노드 삽입의 수행시간은 $O(h)$이며, 여기서 h는 트리의 깊이 = $log_2n$ + 1이다.

### 5.3 힙의 노드 추가 알고리즘

```
/* 힙에 데이터를 삽입하는 함수 */
void insert_max_heap(element item, int *n) {
    int i;
    if(HEAP_FULL(*n)) {
        fprintf(stderr,"The heap is full. \n");
        exit(1);
    }
    i = ++(*n);
    while((i!=1)&&(item.key>heap[i/2].key)) { /*1*/
        heap[i] = heap[i/2];
        i /= 2;
    }
    heap[i] = item;
}
```
### 5.4 힙의 노드 삭제

힙에서 삭제는 항상 루트 노드(가장 큰 데이터)를 지운다. 삭제 후에도 완전 이진 트리가 되도록 재구성한다.

재구성 방법:

1. 마지막 레벨의 마지막 노드를 루트로 올린다.
2. 올라온 루트를 왼쪽 또는 오른쪽 자식 중 **더 큰 값**과 교환한다(두 자식 중 하나는 현재 트리에서 가장 큰 값이다).
3. 이 과정을 트리 아래로 내려가며 반복한다.

자식 노드의 위치는 왼쪽 자식이 `2·i`, 오른쪽 자식이 `2·i + 1`이다. 삭제 수행시간은 $O(h)$이며 h는 트리의 깊이 = $log_2n$ + 1이다.

삭제 예: 루트 20을 삭제하면 마지막 노드 10을 루트로 올리고, 자식과 비교·교환하며 내려가 `15 / (14, 2) / (10)` 형태로 재구성된다.

### 5.5 힙의 노드 삭제 알고리즘

```
/* 힙에서 데이터를 삭제하는 함수 */
element delete_max_heap(int *n) {
    element item, temp;
    if(HEAP_EMPTY(*n)) {
        fprintf(stderr,"The heap is empty\n");
        exit(1); }
    item = heap[1];
    temp = heap[(*n)--];
    parent = 1; child = 2;
    while(child <= *n) {
        if((child < *n) && (heap[child].key < heap[child+1].key))
            child++;
        if(temp.key>=heap[child].key) break;
        heap[parent] = heap[child];
        parent = child;
        child *= 2; }
    heap[parent] = temp;
    return item;
}
```
### 5.6 힙 정렬의 개념

힙 구조(Max Heap)를 이용해 정렬한다. 힙 정렬은 완전 이진 트리를 여러 번 다듬어(Adjust) 힙 구조를 만들고, 다시 다듬기를 반복하며 정렬하는 방법이다.

1. 리스트를 배열에 저장해 힙을 만든다.
   - Adjust 알고리즘을 n/2번 적용해 완전 이진 트리 힙을 구성한다.
2. 힙에서 n개의 데이터를 삭제하고 힙을 재구성하는 과정을 반복한다.
   - 삭제는 항상 루트에서 실행하며 가장 큰 값을 지운다.
   - Adjust 알고리즘을 n-1번 수행한다.
3. 2번에서 삭제된 노드를 배열에 차례로 저장하면 정렬된 리스트가 된다.
   - 실제로는 힙이 저장된 배열에 다시 저장한다.

시간 복잡도는 평균과 최악 모두 $O(nlog_2n)$이다. 이진 트리를 힙으로 만드는 재구성(adjust) 시간은 $O(h)$이며 h는 트리의 깊이다.

### 5.7 힙 정렬 알고리즘

```
void adjust(element list[], int root, int n) {
    int child, rootkey; element temp;
    temp = list[root];
    rootkey = list[root].key;
    child = 2 * root; /* left child */
    while(child <= n) {
        if((child < n) &&
                (list[child].key < list[child+1].key))
                child++;
        if(rootkey > list[child].key) break;
        else {
                list[child/2] = list[child];
                child *= 2;
        }
    }
    list[child/2] = temp;
}
```
```
/* 힙 정렬 */
void heapsort(element list[], int n) {
    int i, j;
    element temp;
    for(i = n / 2; i > 0; i--) /*1*/
        adjust (list, i, n);
    for(i = n - 1; i > 0; i--) { /*2*/
        SWAP(list[1], list[i + 1], temp);
        adjust (list, 1, i);
    }
}
```
### 5.8 힙 정렬의 예

입력 데이터 `(26, 5, 77, 1, 61, 11, 59, 15, 48, 19)`를 배열 첨자 1부터 저장해 힙 구조로 만든 뒤, 루트(최댓값)를 하나씩 빼내며 재구성하는 과정을 반복한다.

재구성 흐름 요약:

- 초기 배열을 완전 이진 트리로 보고 adjust로 Max Heap을 만든다 -> 루트가 77이 된다.
- 77을 삭제(마지막에 저장)하고 5를 루트로 올려 재구성 -> 루트 61.
- 61을 삭제하고 1을 루트로 올려 재구성 -> 루트 59.
- 5를 재구성 -> 루트 48. 이렇게 매번 최댓값이 배열 뒤쪽에 차곡차곡 확정되어 정렬이 완성된다.

### 5.9 힙 정렬의 성능 분석

힙 정렬 수행시간은 "힙 구성시간 + n개 데이터의 삭제 및 재구성시간"이다.

```
힙정렬 수행시간 = 힙 구성시간 + n개의 데이터 삭제 및 재구성시간
             = 힙 구성시간 + (log₂n + log₂(n-1) + ··· + log₂2)
             = (log₂n + log₂(n-1) + ··· + log₂2) + (log₂n + log₂(n-1) + ··· + log₂2)
             = O(n·log₂n)
```
루트 삭제 자체는 $O(1)$이고, 삭제 후 재구성이 트리 높이 h = $log_2n$만큼 걸리므로 전체가 $O(nlog_2n)$이 된다.

## 6. 기타 정렬

### 6.1 쉘(shell) 정렬

일정한 간격으로 떨어진 자료들끼리 부분집합을 만들고, 각 부분집합에 삽입 정렬을 적용하는 작업을 반복하며 전체를 정렬한다. 전체를 한 번에 삽입 정렬하는 것보다 부분집합으로 나눠 정렬하면 비교·교환 연산이 줄어든다.

부분집합 구성:

- 부분집합의 기준이 되는 간격을 매개변수 `h`에 저장한다.
- 한 단계가 끝날 때마다 `h`를 줄이고 쉘 정렬을 다시 호출한다. `h`가 1이 될 때까지 반복한다.

쉘 정렬의 성능은 매개변수 `h` 값에 따라 달라진다. 자료 특성에 맞는 매개변수 생성 함수를 쓰며, 일반적으로 원소 개수의 1/2을 `h`의 시작값으로 삼고 단계마다 절반으로 줄여 반복한다.

예: 입력 `10 8 6 20 4 3 22 1 0 15 16`을 간격 5, 간격 3, 간격 1 순으로 정렬하면 부분 리스트가 점점 정돈되어 `0 1 3 4 6 8 10 15 16 20 22`가 된다.

### 6.2 머지(merge) 정렬

리스트를 균등한 크기 두 개로 분할하고, 분할된 부분리스트를 정렬한 뒤 합쳐 전체를 정렬한다. 분할 정복(divide and conquer) 방법을 쓴다: 문제를 더 작은 두 문제로 나누고 각각 해결한 다음 결과를 모아 원래 문제를 푼다. 나뉜 문제가 여전히 크면 분할 정복을 다시 적용한다(재귀 호출).

세 단계로 요약된다:

1. 분할(Divide): 배열을 같은 크기의 부분 배열 2개로 나눈다.
2. 정복(Conquer): 부분 배열을 정렬한다. 크기가 충분히 작지 않으면 재귀 호출로 다시 분할 정복을 적용한다.
3. 결합(Combine): 정렬된 부분 배열을 하나의 배열로 통합한다.

`merge_sort` 유사코드:

```
merge_sort(list, left, right)

1 if left < right
2         mid = (left+right)/2;
3         merge_sort(list, left, mid);
4         merge_sort(list, mid+1, right);
5         merge(list, left, mid, right);
```
`merge` 유사코드(정렬된 두 부분 배열을 합침):

```
merge(list, left, mid, right):
// 2개의 인접한 배열 list[left..mid]와 list[mid+1..right]를 합병

i←left;
j←mid+1;
k←left;
while i≤left and j≤right do
    if(list[i]<list[j])
            then
              sorted[k]←list[i];
              k++;
              i++;
            else
              sorted[k]←list[j];
              k++;
              j++;
요소가 남아있는 부분배열을 sorted로 복사한다;
sorted를 list로 복사한다;
```
### 6.3 기수(radix) 정렬

대부분의 정렬은 레코드를 서로 비교해 순서를 정하지만, 기수 정렬(radix sort)은 비교하지 않고 정렬한다. 그래서 비교 기반 정렬의 하한인 O(n·log(n))보다 빠를 수 있으며, O(dn)의 시간 복잡도를 가진다(대부분 d < 10 이하).

단점은 정렬 가능한 레코드 타입이 한정된다는 점이다. 실수·한글·한자 등은 정렬할 수 없고, 키가 같은 길이의 숫자나 단순 문자(알파벳 등)여야 한다.

동작: 자릿수에 따라 값을 버켓(bucket)에 넣었다가 순서대로 꺼내면 정렬된다.

- 한 자리 수 예 `(8, 2, 7, 3, 5)`: 각 값을 자기 숫자에 해당하는 버켓에 넣고 0번부터 꺼내면 `2 3 5 7 8`.
- 두 자리 수 예 `(28, 93, 39, 81, 62, 72, 38, 26)`: 먼저 낮은 자리(1의 자리)로 분류해 꺼낸 뒤, 그 순서를 다시 높은 자리(10의 자리)로 분류하면 `26 28 38 39 62 72 81 93`이 된다.

버켓은 큐로 구현한다. 버켓 개수는 키 표현 방식과 밀접한데, 이진법이면 2개, 알파벳 문자면 26개, 십진법이면 10개가 필요하다.

`RadixSort` 유사코드:

```
RadixSort(list, n):

for d←LSD의 위치 to MSD의 위치 do
{
  d번째 자릿수에 따라 0번부터 9번 버켓에 넣는다.
  버켓에서 숫자들을 순차적으로 읽어서 하나의 리스트로 합친다.
  d++;
}
```
