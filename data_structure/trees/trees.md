## 핵심 요약

- 트리는 사이클이 없는 그래프이며 계층 구조를 이룬다. 루트와 부속 트리(subtree)들로 구성된다.
- **이진 트리**는 자식이 2개 이하인 트리. 일반 트리도 왼쪽자식-오른쪽형제 표현을 거치면 이진 트리로 변환된다.
- 저장 방식: 배열(완전 이진 트리에 효과적), 연결리스트(일반적). 탐색 방식: 중위(LVR), 전위(VLR), 후위(LRV), 레벨(큐 이용).
- **쓰레드 이진 트리**는 비어 있는 링크에 중위 순서의 이전/다음 노드를 저장해 탐색을 빠르게 한다.
- **이진 검색 트리**는 `key(왼쪽) ≤ key(루트) ≤ key(오른쪽)` 조건을 만족하며, 탐색·삽입·삭제 시간복잡도는 트리 높이 `h`에 비례한다(최선 `log₂n`, 최악 `n`).

## 1. 트리의 개념

### 1.1 트리의 정의

- 트리는 1개 이상의 노드를 갖는 집합으로 노드들은 다음 조건을 만족한다.
- 트리에는 루트(root)라고 부르는 특별한 노드가 있다.
- 다른 노드들은 n개의 부속 트리(subtree)에 속한다.
- T₁, T₂, …, Tₙ으로 나누어지며 Tᵢ 각각은 루트의 부속 트리라고 부른다.
- 트리는 사이클이 없는 그래프(acyclic graph)이며 계층 구조를 이룬다.

자료구조 트리(tree)는 나무를 거꾸로 그린다. 부속 트리 T₁, T₂, T₃는 다시 트리 구조를 이룬다.

### 1.2 트리의 응용

트리 자료구조의 필요성: 트리 구조에 저장하면 더 효율적인 자료들이 있기 때문이다. 예를 들면, 계층적인 데이터 형태들은 트리에 저장하면 자연스럽게 표현된다.

- 회사나 정부의 조직 구조
- 나라, 지방, 시/군별, 계층적인 데이터의 저장
- 인덱스

### 1.3 트리의 용어


| 용어                               | 정의                                          |
| ------------------------------------ | ----------------------------------------------- |
| 노드의 차수 (degree)               | 노드의 부속 트리의 개수                       |
| 트리의 차수 (degree of tree)       | 트리의 최대 차수                              |
| 단말 노드 (leaf, terminal)         | 차수가 0인 노드, 즉 맨 끝에 달린 노드         |
| 내부 노드 (internal, non-terminal) | 차수가 1 이상인 노드                          |
| 부모 (parent)                      | 부속 트리(subtree)를 가진 노드                |
| 자식 (child)                       | 부모에 속하는 부속노드                        |
| 형제 (sibling)                     | 부모가 같은 자식 노드들                       |
| 조상 (ancestor)                    | 노드의 부모 노드들의 총 집합                  |
| 자손 (descendant)                  | 노드의 부속 트리에 있는 모든 노드들           |
| 레벨 (level)                       | 루트 노드들로부터 깊이 (루트 노드의 레벨 = 1) |
| 트리의 깊이 (depth of tree)        | 트리에 속한 노드의 최대 레벨                  |

### 1.4 n-링크 표현법

노드에 n개의 링크를 두고 자식의 개수만큼 링크에 저장한다. 모든 노드는 자식 노드 수에 관계없이 최대 n개의 링크를 갖는다. 각 링크는 부속 트리가 저장된 곳을 링크한다.

차수가 n인 경우 표현된 노드:

```
| data | link 1 | link 2 | ... | link n |
```

참고: 트리를 리스트 형태로 표현하는 방법 - 괄호를 사용하여 같은 레벨에 있는 노드들을 같은 괄호로 묶는다.

예: `(A(B(E(K,L),F),C(G),D(H(M),I,J)))`

### 1.5 왼쪽자식노드-오른쪽형제노드 표현 방법

- 모든 노드에 링크를 2개를 둔다.
- 첫째 링크는 첫번째 자식노드를 표현하고
- 둘째 링크는 자신의 오른쪽 형제 노드를 표현한다.
- 노드의 길이가 2개로 고정되기 때문에 n-링크 방법보다 간편하다.

```
|           data             |
| left child | right sibling |
```

### 1.6 차수가 n인 트리를 차수가 2인 트리로 저장하는 방법

- 트리를 왼쪽자식노드-오른쪽형제노드로 변환하여 그린다.
- 45도 시계 방향으로 돌리면 된다.
- 모든 노드가 2개 이하의 자식 노드를 갖는다.
- 차수가 n인 트리가 차수가 2인 트리가 된다. (이진 트리)

## 2. 이진 트리

### 2.1 일반 트리와 이진 트리

- 일반 트리도 이진 트리로 변형하여 저장하는 것이 더 효율적이다.
- 일반 트리에서 자식노드의 개수가 변하기 때문에 저장 방법이 쉽지 않다.

### 2.2 이진 트리

자식 노드의 수가 2개 이하인 것을 이진 트리(binary tree)라고 한다. 대부분 응용에서 일반 트리 보다는 원래부터 이진 트리로 표현된 문제가 많다.

> **정의)** 이진 트리(a binary tree)는 유한개의 노드로 구성된 트리로
>
> 1) 비어있거나 혹은
> 2) 루트노드와 2개의 부속 트리로 구성된다.
>
> 2개의 부속 트리는 왼쪽 부속 트리, 오른쪽 부속 트리라고 부른다.

노드가 없는 경우도 이진 트리의 일종이다.

### 2.3 이진 트리의 성질

- 이진 트리는 자식의 개수가 2개 이하인 일반 트리와 약간 다르다.
- 노드가 없는 트리(empty node)도 이진 트리가 된다.
- 부속 트리(자식 노드)에 순서가 있다.
- 이진 트리의 최대 레벨이 i 인 경우 트리의 최대 노드의 개수는 2ⁱ-1이다.
  - 레벨 1의 최대 노드 개수 = 1
  - 레벨 2의 최대 노드 개수 = 2
  - …
  - 레벨 i의 최대 노드 개수 = 2^(i-1)
  - 레벨 i인 트리의 최대 노드는 = 1 + 2 + 4 + 8 + … + 2^(i-1) = 2ⁱ - 1
- n개의 노드를 가진 이진 트리에서 간선의 수: (n-1) 개
- 높이가 h인 이진 트리에서 노드 수
  - 최소: h개
  - 최대: 2ʰ - 1
- n개의 노드를 가지는 이진 트리의 높이
  - 최소: log₂(n+1)
  - 최대: n
- n₀ = n₂ + 1  (n₀는 차수가 0인 노드의 수, n₂는 차수가 2인 노드의 수)

### 2.4 이진 트리의 예

- **포화(full) 이진 트리**: 모든 레벨이 가득 찬 이진 트리. (예: 깊이=4, 노드 15개)
- **Skewed 이진 트리**: 한쪽으로 치우친 이진 트리.
- **완전(complete) 이진 트리**: 마지막 레벨을 제외하고 모두 채워지고, 마지막 레벨은 왼쪽부터 채워진 이진 트리.

## 3. 이진 트리의 저장과 탐색

### 3.1 추상데이터타입: 일반 트리

> **객체:** 노드는 트리의 각 요소, 간선은 노드 간의 연결, 루트는 트리의 시작점인 노드, 부모/자식은 계층적 관계이다. 리프 노드는 자식이 없는 노드이고 서브 트리는 특정 노드를 루트로 하는 트리이다.


| 연산              | 설명                                                 |
| ------------------- | ------------------------------------------------------ |
| `Create()`        | 빈 트리를 생성한다.                                  |
| `IsEmpty(T)`      | 트리 T가 비어 있는지 확인한다.                       |
| `Root(T)`         | 트리 T의 루트 노드를 반환한다.                       |
| `Parent(n)`       | 노드 n의 부모를 반환한다.                            |
| `Num_Children(n)` | 노드 n의 차수(자식들의 수)를 반환한다.               |
| `Children(n)`     | 노드 n의 자식들을 반환한다.                          |
| `AddChild(p, c)`  | 노드 p에 자식 노드 c를 추가한다.                     |
| `Delete(n)`       | 노드 n과 그 하위 서브 트리를 삭제한다.               |
| `Traverse(T)`     | 트리 T를 특정 순서로 순회한다. (전위/중위/후위 순회) |

**제한조건:** 루트를 제외한 노드는 하나의 부모만 가질 수 있고 트리는 사이클(cycle)이 없는 연결 그래프이다.

### 3.2 추상데이터타입: 이진 트리

각 노드가 최대 두 개의 자식을 가지는 트리이다. 일반 트리의 연산에 다음의 연산이 추가된다.


| 연산                | 설명                               |
| --------------------- | ------------------------------------ |
| `LeftChild(n)`      | 노드 n의 왼쪽 자식을 반환한다.     |
| `RightChild(n)`     | 노드 n의 오른쪽 자식을 반환한다.   |
| `InsertLeft(p, v)`  | 노드 p의 왼쪽에 값 v를 삽입한다.   |
| `InsertRight(p, v)` | 노드 p의 오른쪽에 값 v를 삽입한다. |

### 3.3 배열을 이용한 이진 트리의 저장

- 트리의 레벨 순서대로 배열에 저장을 해두는 방법이다.
- 트리의 노드를 레벨순서대로 왼쪽에서 오른쪽으로 저장한다.
- 배열이름을 `T[]`라고 하면 루트노드는 `T[0]`에, 레벨2의 첫째노드는 `T[1]`에, 둘째노드는 `T[2]`에, …, 저장하는 방식이다.

배열에 저장할 경우 임의의 배열 원소의 부모와 왼쪽, 오른쪽 자식을 찾는 함수는 다음과 같이 된다 (첨자가 0부터 시작할 경우).

```
1) 부모 노드의 위치 -
   parent(i) = (i - 1) / 2   if i ≠ 0
   parent(i) = 0             if i = 0   (루트노드는 부모가 없다.)
2) 왼쪽자식의 위치  -  left_child(i)  = 2·i + 1
3) 오른쪽자식의 위치 -  right_child(i) = 2·i + 2
```

예를 들어 `T[6]`의 부모는 `T[(6-1)/2]`이고 `T[3]` 노드의 왼쪽자식은 `T[(3*2)+1]`이다. `T[1]` 노드의 오른쪽 자식 노드의 위치는 `T[4]`이다.

### 3.4 배열을 이용한 이진 트리의 문제점

- 배열의 이용하지 않는 저장 공간이 많다.
- 깊이가 k인 트리에서 전체 필요한 공간은 S(k) = 2ᵏ - 1 이지만 skewed 이진 트리 처럼 깊이에 비하여 노드 수가 적은 경우 기억 공간 활용율이 낮다.
- complete(완전) 이진 트리의 저장에는 효과적이다.
- 트리의 최대 깊이를 대비하여 많은 기억장소를 확보하고, 트리가 예상보다 커지면 프로그램 수행을 종료해야 한다.

### 3.5 연결리스트를 이용한 이진 트리

각 노드는 다음으로 구성된다.

- 데이터
- 왼쪽자식에 대한 포인터
- 오른쪽자식에 대한 포인터

| left_child | data | right_child |
필드를 한 개 더 추가하여 부모노드에 대한 포인터를 저장할 수도 있다. 그러나 트리를 다룰 때 링크 3개를 관리해야 하므로 복잡하여 잘 사용하지 않는다.

Python으로 표현하면 다음과 같다.

```python
class TNode:                                 # 이진트리를 위한 노드 클래스
    def __init__(self, data, left, right):   # 생성자
        self.data = data                     # 노드의 데이터
        self.left = left                     # 왼쪽 자식을 위한 링크
        self.right = right                   # 오른쪽 자식을 위한 링크
```
### 3.6 이진 트리의 탐색

트리의 탐색(traversal)은 트리의 각 노드를 방문하는 작업을 말한다.

- **레벨 순**: 레벨이 낮은 순으로 방문
- 왼쪽트리 L -> A -> 오른쪽트리 R
- 왼쪽트리 L -> 오른쪽트리 R -> A
- A -> 왼쪽트리 L -> 오른쪽트리 R

강의 예제 트리(루트 A, 왼쪽 B-D-E-H-I, 오른쪽 C-F-G)에서 결과:


| 탐색 방식            | 순서                   | 결과              |
| ---------------------- | ------------------------ | ------------------- |
| 레벨탐색             | 레벨이 낮은 순         | A B C D E F G H I |
| 중위탐색 (inorder)   | LVR (Left Visit Right) | H D I B E A F C G |
| 전위탐색 (preorder)  | VLR (Visit Left Right) | A B D H I E C F G |
| 후위탐색 (postorder) | LRV (Left Right Visit) | H I D E B F G C A |

#### 중위 탐색

중위 탐색은 왼쪽 트리 -> 루트노드 -> 오른쪽 트리 순으로 방문을 하게 된다. 주의할 점은 왼쪽 트리를 방문할 때 왼쪽 트리 자체가 트리이기 때문에 왼쪽 트리 안에서도 다시 중위 탐색을 한다. 그러므로 왼쪽 트리로 간 다음 왼쪽 트리의 왼쪽 트리, 왼쪽 트리의 루트노드, 왼쪽 트리의 오른쪽 트리 순이 된다. 트리 탐색 알고리즘은 순환 알고리즘(recursive algorithm)이 간단하다.

중위 탐색의 예 - 수식 트리(expression tree)에 대한 중위 탐색 결과: `A / B * C * D + E` (중위표기식)

#### 전위 탐색

전위 탐색은 루트노드 -> 왼쪽트리 -> 오른쪽트리 순으로 방문을 하게 된다. 중위탐색과 마찬가지로 왼쪽 트리를 방문할 때 왼쪽 트리 자체가 트리이기 때문에 왼쪽 트리에서도 다시 전위 탐색을 한다. 노드가 1개 있는 트리는 그냥 왼쪽, 오른쪽 트리가 없기 때문에 바로 방문을 한다.

#### 후위 탐색

후위 탐색은 왼쪽 트리 -> 오른쪽 트리 -> 루트노드 순으로 방문을 하게 된다.

#### 레벨 탐색

레벨 탐색은 레벨1 노드들 -> 레벨2 노드들 -> 레벨3 노드들 -> … 순서대로 탐색을 한다. 레벨 i를 탐색할 때 방문 노드의 자식 노드를 저장을 해 둔 다음 레벨 i를 다 방문하면 다음 방문지는 저장해둔 노드를 꺼내어 방문한다. 이 때 저장해 둔 노드들은 먼저 저장된 노드를 먼저 꺼내어 방문을 하면 된다. 즉 큐(FIFO) 자료구조가 되는 것이다.

## 4. 이진 트리 알고리즘

### 4.1 이진 트리의 노드 계산

탐색 트리 안의 노드의 개수를 계산한다. 각각의 서브트리에 대하여 순환 호출한 다음, 반환되는 값에 1을 더하여 반환한다.

```python
def count_node(n):
    if n is not None:
        return 0                                    # 공백트리이면 0
    else:                                           # 좌우 서브트리의 노드수의 합 + 1
        return 1 + count_node(n.left) + count_node(n.right)
```
### 4.2 이진 트리의 높이 계산

서브트리에 대하여 순환호출하고 서브 트리들의 반환값 중에서 최대값을 구하여 반환한다.

`H = max(H_left, H_right)`

```python
def calc_height(n):
    if n is not None:
        return 0                                # 공백트리이면 0
    hLeft = calc_height(n.left)                 # 왼쪽 트리의 높이
    hRight = calc_height(n.right)               # 오른쪽 트리의 높이
    if (hLeft > hRight):                        # 더 높은 높이에 1을 더해 반환
        return hLeft + 1
    else:
        return hRight + 1
```
### 4.3 이진 트리의 복사

똑같은 이진트리를 한 개 더 만든다면 트리를 탐색하면서 새로운 노드를 만날 때마다 노드를 복사하여야 한다. (후위 탐색 이용)

### 4.4 이진 트리의 비교

두개의 이진트리를 탐색하면서 노드를 만날 때마다 두 트리의 노드의 값을 비교하면 된다. 탐색 방법은 여러가지 탐색 방법 중 택하면 되지만 전위탐색 방법을 이용한다.

## 5. 쓰레드 이진 트리

### 5.1 쓰레드 이진 트리의 필요성

문제 제기: 이진 트리를 탐색할 때 일정한 순서에 따라 노드를 탐색하게 된다. 이때 노드의 순서에 따라 미리 다음 노드를 연결시켜 놓으면 훨씬 검색 속도가 빠르게 된다.

방법: 트리의 링크에서 자식이 없는 노드에 링크 필드 값을 NULL로 비워 두지 말고 다음 방문할 곳이나 바로 앞 방문했던 노드를 가리키도록 한다.

트리의 전체 노드 수는 N개이고 링크의 수는 2N개이며 이 중 N+1개의 링크는 비어 있게 된다. 이 N+1개의 링크를 활용한다. 이 링크를 **thread**라고 부른다.

### 5.2 쓰레드 이진 트리 만들기

비어 있는 링크 값이 왼쪽인지 오른쪽인지에 따라 다음과 같이 만든다.

- 왼쪽 링크가 비어 있으면 (`if ptr->left_child is null`)
  -> 노드의 링크 값을 **중위 탐색 순서의 바로 전 노드** 값을 저장한다.
- 오른쪽 링크가 비어 있으면 (`if ptr->right_child is null`)
  -> 노드의 링크 값을 **중위 탐색 순서의 바로 다음 노드** 값을 저장한다.

노드의 링크에 저장된 값이 자식 노드에 대한 포인터인지, 쓰레드인지 구분하기 위해 필드를 두어서 표시하여야 한다.

필드 변수 이름: `left_thread` and `right_thread`


| 변수 값                     | 의미                                    |
| ----------------------------- | ----------------------------------------- |
| `ptr->left_thread = TRUE`   | `ptr->left_child`가 thread 값일 경우    |
| `ptr->left_thread = FALSE`  | `ptr->left_child`가 왼쪽 자식일 경우    |
| `ptr->right_thread = TRUE`  | `ptr->right_child`가 thread 값일 경우   |
| `ptr->right_thread = FALSE` | `ptr->right_child`가 오른쪽 자식일 경우 |

쓰레드 트리를 만들기 위해서는 일반 트리와 같으나 쓰레드인지 구분하는 필드를 두게 된다.

```
| left_thread | left_child | data | right_child | right_thread |
```
### 5.3 쓰레드 이진 트리의 탐색

이진 트리를 쓰레드 트리로 바꾼 후에는 중위탐색을 편하게 할 수 있다. 자식노드가 있으면 자식노드에 대한 링크 값을 바로 알 수 있고 자식노드가 없으면 쓰레드 링크에 다음 방문지 링크 값이 포함되어 있으므로 역시 바로 찾을 수 있다.

먼저 임의의 노드의 다음 방문 링크를 찾는 `insuccessor()` 함수:

```
insuccessor() {
    find the inorder successor of ptr
    - if ptr->right_thread = TRUE,
        then ptr->right_child
    - otherwise
        follow a path of left-child links from the right-child of ptr
        until we reach a node with left_thread = TRUE
}
```
쓰레드 트리의 중위탐색 알고리즘은 루트 노드에서 시작하여서 다음 노드를 계속 찾아 나가면 된다.

## 6. 이진 검색 트리

### 6.1 이진 검색 트리

- 검색작업을 효율적으로 하기 위한 자료구조
- `key(왼쪽서브트리) < key(루트노드) < key(오른쪽서브트리)`
- 이진탐색트리를 중위순회하면 오름차순으로 정렬된 값을 얻을 수 있다.

### 6.2 이진 검색 트리에서의 검색

- 비교한 결과가 같으면 탐색이 성공적으로 끝난다.
- 비교한 결과가, 주어진 키 값이 루트 노드의 키값보다 작으면 탐색은 이 루트 노드의 왼쪽 자식을 기준으로 다시 시작한다.
- 비교한 결과가, 주어진 키 값이 루트 노드의 키값보다 크면 탐색은 이 루트 노드의 오른쪽 자식을 기준으로 다시 시작한다.

알고리즘:

```
search(x, k) {
    if x = NULL
        then return NULL;
    if k = x->key
        then return x;
    else if k < x->key
        then return search(x->left, k);
        else return search(x->right, k);
}
```
### 6.3 이진 검색 트리의 노드 삽입

이진 검색 트리에 원소를 삽입하기 위해서는 먼저 검색을 수행하는 것이 필요하다. 검색에 실패한 위치가 바로 새로운 노드를 삽입하는 위치.

알고리즘:

```
insert_node(T, z)

p ← NULL;
t ← root;
while t ≠ NULL do
    p ← t;
    if z->key < p->key
        then t ← p->left;
        else t ← p->right;
if p = NULL
    then root ← z;             // 트리가 비어있음
    else if z->key < p->key
        then p->left ← z
        else p->right ← z
```
### 6.4 이진 검색 트리의 노드 삭제

이진 검색 트리의 노드 삭제 3가지 CASE:

① 삭제하려는 노드가 단말 노드 일 경우
② 삭제하려는 노드가 하나의 왼쪽이나 오른쪽 서브 트리 중 하나만 가지고 있는 경우
③ 삭제하려는 노드가 두개의 서브 트리 모두 가지고 있는 경우


| CASE | 처리 방법                                                                                                             |
| ------ | ----------------------------------------------------------------------------------------------------------------------- |
| 1    | 삭제하려는 노드가 단말 노드일 경우, 단말 노드의 부모 노드를 찾아서 연결을 끊으면 된다.                                |
| 2    | 삭제되는 노드가 왼쪽이나 오른쪽 서브 트리중 하나만 갖고 있을 때, 그 노드는 삭제하고 서브 트리는 부모 노드에 붙여준다. |
| 3    | 삭제 노드와 가장 비슷한 값을 가진 노드를 삭제 노드 위치로 가져온다.                                                   |

### 6.5 이진 검색 트리의 성능 분석

이진 검색 트리에서의 탐색, 삽입, 삭제 연산의 시간 복잡도는 트리의 높이를 h라고 했을때 h에 비례한다.

균형적인 이진 트리에서 높이 = ⌈log₂n⌉

**최선의 경우**

① 이진 트리가 균형적으로 생성되어 있는 경우
② h = log₂n

**최악의 경우**

① 한쪽으로 치우친 경사 이진 트리의 경우
② h = n
③ 순차탐색과 시간복잡도가 같다.
