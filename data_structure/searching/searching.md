## 핵심 요약

- 검색은 키 값으로 데이터를 찾는 작업이며, 방식에 따라 속도가 크게 갈린다.
- 선형 $O(n)$ -> 이진 $O(\log n)$ -> 해싱은 비교 없이 $O(1)$에 가깝게 접근.
- 트리 계열(BST, AVL, 2-3)은 높이가 곧 성능이며, 균형을 유지할수록 $O(\log n)$에 가깝다.
- BST는 한쪽으로 치우치면 $O(n)$까지 나빠지고, AVL, 2-3 트리는 이를 막는 균형 구조다.

## 1. 선형 검색

### 1.1 개념

배열 앞에서부터 원소를 하나씩 키와 맞춰 보며 찾는 방식이다. 정렬 여부와
상관없이 쓸 수 있고 구현이 가장 단순하다. 여기서는 배열 `[10, 13, 25, 4,
15, 20, 5, 29, 14, 21]`에서 화살표가 앞에서부터 이동하며 `find_key`와
값을 비교하는 그림으로 설명한다.


```
int sequential_search(int keys[], int find_key, int n)
{
    int i = 0;
    while (i <= n)
    {   i++
        if (keys[i] == find_key) return(i);
    }
    return(0);
}
```

### 1.2 성능 분석

운이 좋으면 첫 비교에서 찾지만, 최악은 찾는 값이 맨 끝에 있거나 아예 없는
경우로 n개를 모두 비교해야 한다. 평균적으로는 절반인 n/2번 비교하므로
시간복잡도는 $O(n)$이다. 데이터가 1,000~10,000개 수준이면 부담이 적지만, 백만~억
단위가 되면 실용성이 떨어진다. 이후 다루는 검색 알고리즘들은 대체로
$O(\log n)$ 수준으로 이보다 빠르다.

## 2. 이진 검색

### 2.1 개념

**정렬된** 데이터에서만 쓸 수 있는 방식이다. 예를 들어 1부터 10,000까지
오름차순 리스트에서 5001을 찾을 때, 처음부터 하나씩 보는 대신 가운데 값과
먼저 비교하는 편이 빠르다. 가운데 값과 비교해서 찾는 값이 더 크면 오른쪽
절반, 더 작으면 왼쪽 절반만 남기고 나머지는 버린다. 비교 한 번마다 후보가
절반으로 줄어드는 것이 핵심이다.

예시: `[9, 15, 16, 19, 21, 39, 51, 65, 76, 85, 99]`에서 65 검색
- 1단계: 65와 가운데 39 비교 -> 오른쪽 절반 `[51, 65, 76, 85, 99]`
- 2단계: 65와 가운데 76 비교 -> 왼쪽 절반 `[51, 65]`

### 2.2 알고리즘

```
BinarySearch(int list[], int n, int key){
    left = 0
    right = n - 1
    while (left <= right)
    {
        mid = (left + right) / 2
        if (list[mid] == key) return mid
        else if (list[mid] < key) left = mid + 1
        else right = mid - 1
    }
    return -1
}
```

### 2.3 성능 분석

while 반복 횟수가 곧 검색 시간이다. 못 찾을 때마다 후보 리스트가 절반이
되므로 비교 대상 개수는 n -> n/2 -> n/4 -> n/8 -> … 로 줄어든다.

$n = 2^k$ 이라고 하면 개수는 $2^k -> 2^(k-1) -> … -> 2^0$ 으로 변하고, 1개가 될
때까지 총 k번 반복한다. 여기서 양변에 밑이 2인 log를 취하면
$\log_2 n = k$ 이므로 $\log n$번 반복한다. 따라서 복잡도는 **$O(\log n)$** 이다.

## 3. 해싱

### 3.1 개념

찾으려는 키 값을 계산(조작)해서 저장 위치를 곧바로 얻어 내는 방식이다.
예시로, 키를 제곱한 뒤 끝 두 자리를 위치로 쓴다고 하면 키 123은
123x123=15129 이므로 끝 두 자리인 29를 써서 `X[29]`에 저장된다. 즉 키만
알면 비교 없이 위치를 계산할 수 있다. 선형 검색이 평균 n/2번, 이진 검색이
$\log n$번 비교하는 것과 달리 해싱은 비교 없이 바로 접근하므로 검색 중에서는
가장 빠르다.

### 3.2 해싱의 용어

| 용어 | 설명 |
|------|------|
| 해시테이블 | M개의 버켓(bucket)으로 구성된 테이블. 원소 `ht[0] … ht[M-1]`을 가지며, 버켓 하나에 s개의 슬롯(slot)을 둘 수 있다 |
| 충돌(collision) | 서로 다른 두 키 k1, k2에 대해 `h(k1) = h(k2)`가 되는 경우 |
| 오버플로우(overflow) | 충돌이 버켓의 슬롯 수보다 많이 생기는 경우. 반드시 해결 방법이 필요하다 |
| 적재밀도(loading density) | (저장된 항목 수) ÷ (버켓 수) = n / M |

### 3.3 해시함수 예시

알파벳 문자열 키의 해시함수를 "첫 글자의 순서"로 정하면 h("array")=0,
h("binary")=1 처럼 된다. 입력 `array, binary, bubble, file, digit, direct,
zero, bucket`을 넣으면 같은 첫 글자끼리 같은 버켓으로 몰린다. 예를 들어
b로 시작하는 binary, bubble, bucket이 버켓 1에 몰리는데, 슬롯이 2개뿐이면
세 번째인 bucket은 오버플로우로 저장하지 못한다.

### 3.4 좋은 해시함수의 조건

- 충돌이 적어야 한다.
- 해시값이 테이블 주소 범위 안에 고르게 퍼져야 한다.
- 계산이 빨라야 한다.

### 3.5 해시함수의 종류

| 종류 | 방식 |
|------|------|
| 제산 함수 | `h(k) = k mod M`, 테이블 크기 M은 소수(prime)로 선택 |
| 폴딩 함수 | 키를 여러 조각으로 나눠 더함. 이동 폴딩(shift)과 경계 폴딩(boundary)이 있다 |
| 중간제곱 함수 | 키를 제곱한 뒤 중간의 몇 비트를 뽑아 주소로 사용 |
| 비트추출 함수 | 키를 이진수로 보고 임의 위치의 k개 비트를 주소로 사용 |
| 숫자 분석 방법 | 키 자릿수 중 편중이 적은 자리들을 골라 테이블 크기에 맞게 조합 |

폴딩 함수 예 (키를 123, 203, 241, 112, 20으로 분할):
- 이동 폴딩: 123 + 203 + 241 + 112 + 20 = 699
- 경계 폴딩: 이웃한 조각을 뒤집어 더함 -> 123 + 302 + 241 + 211 + 20 = 897

### 3.6 오버플로우 해결 방안

Linear Probing, Quadratic Probing, Double Hashing, Chaining이 있다.
아래 예들은 모두 첫 해시함수 `h(k) = k mod 7`, 입력 `(8, 1, 9, 6, 13)`을
기준으로 한다.

#### 3.6.1 Linear Probing (선형 조사)

충돌이 `ht[k]`에서 나면 `ht[k+1]`이 비었는지 보고, 차 있으면 `ht[k+2]` …
식으로 빈 자리가 나올 때까지 한 칸씩 뒤로 조사한다. 테이블 끝에 닿으면 다시
맨 앞부터 보고, 출발점으로 되돌아오면 테이블이 가득 찬 것이다. 조사 위치는
`h(k), h(k)+1, h(k)+2, …` 순이다.

```
1단계 (8) : h(8) = 8 mod 7 = 1 (저장)
2단계 (1) : h(1) = 1 mod 7 = 1 (충돌) -> (h(1)+1) mod 7 = 2 (저장)
3단계 (9) : h(9) = 9 mod 7 = 2 (충돌) -> (h(9)+1) mod 7 = 3 (저장)
4단계 (6) : h(6) = 6 mod 7 = 6 (저장)
5단계 (13): h(13) = 13 mod 7 = 6 (충돌) -> (h(13)+1) mod 7 = 0 (저장)
```

#### 3.6.2 Quadratic Probing (이차 조사)

선형 조사와 비슷하지만 다음 위치를 `(h(k) + inc*inc) mod M`
(inc = 0, 1, …, M-1)으로 정한다. 따라서 조사 위치가 `h(k), h(k)+1,
h(k)+4, …` 처럼 제곱 간격으로 벌어진다.

#### 3.6.3 Double Hashing (이중 해싱)

오버플로우가 나면 원래 해시함수와 다른 두 번째 해시함수로 이동 폭을
정한다. `step = C - (k mod C)`로 두고 `h(k), h(k)+step, h(k)+2*step, …`
순으로 조사한다. 아래는 두 번째 함수 `step = 5 - (k mod 5)`를 쓴 경우다.

```
1단계 (8) : h(8) = 1 (저장)
2단계 (1) : h(1) = 1 (충돌) -> (h(1) + (5-(1 mod 5))) mod 7 = (1+5) mod 7 = 5 (저장)
3단계 (9) : h(9) = 2 (저장)
4단계 (6) : h(6) = 6 (저장)
5단계 (13): h(13) = 6 (충돌)
            -> (6 + (5-(13 mod 5))) mod 7 = (6+5) mod 7 = 1 (충돌)
            -> (6 + 2*(5-(13 mod 5))) mod 7 = (6+2*2) mod 7 = 3 (저장)
```

#### 3.6.4 Chaining (체이닝)

각 버켓에 고정 슬롯을 두지 않고 연결 리스트를 매단다. 충돌이 나면 그
버켓의 리스트에 새 노드를 이어 붙이고, 버켓 안에서는 리스트를 순차 탐색한다.
삽입·삭제가 쉽다.

```
1단계 (8) : h(8) = 1 (저장)
2단계 (1) : h(1) = 1 (충돌 -> 버켓 1 리스트에 새 노드 연결)
3단계 (9) : h(9) = 2 (저장)
4단계 (6) : h(6) = 6 (저장)
5단계 (13): h(13) = 6 (충돌 -> 버켓 6 리스트에 새 노드 연결)
```

## 4. 이진 탐색 트리

### 4.1 개념

탐색을 효율적으로 하려고 만든 자료구조로, 모든 노드가 다음을 만족한다.

> key(왼쪽 서브트리) <= key(루트 노드) <= key(오른쪽 서브트리)

이 성질 덕분에 중위순회하면 오름차순으로 정렬된 값을 얻는다.

### 4.2 이진 탐색 트리에서의 검색

- 찾는 값이 노드 키와 같으면 탐색 성공.
- 찾는 값이 노드 키보다 작으면 그 노드의 왼쪽 자식에서 다시 시작.
- 찾는 값이 노드 키보다 크면 그 노드의 오른쪽 자식에서 다시 시작.

### 4.3 검색 알고리즘

순환 구조:

```
TreeNode *search(TreeNode *node, int key)
{
    if ( node == NULL )  return NULL;
    if ( key == node->key ) return node;
    else if ( key < node->key )
        return search(node->left, key);
    else
        return search(node->right, key);
}
```

반복 구조:

```
TreeNode *search(TreeNode *node, int key)
{
    while (node != NULL) {
        if ( key == node->key ) return node;
        else if ( key < node->key ) node = node->left;
        else node = node->right;
    }
    return NULL;  // 탐색에 실패했을 경우 NULL 반환
}
```

### 4.4 노드 삽입

새 원소를 넣으려면 먼저 탐색을 수행한다. 탐색이 실패로 끝난 그 위치가 바로
새 노드를 붙일 자리다.

```
insert_node(T, z)
p <- NULL;
t <- root;
while t ≠ NULL do
    p <- t;
    if z->key < p->key
        then t <- p->left;
        else t <- p->right;
if p = NULL
    then root <- z;            // 트리가 비어있음
    else if z->key < p->key
        then p->left <- z
        else p->right <- z
```

### 4.5 노드 삭제

삭제는 노드가 가진 자식 수에 따라 세 경우로 나뉜다.

| CASE | 상황 | 처리 |
|------|------|------|
| 1 | 단말 노드(자식 없음) | 부모와의 연결만 끊는다 |
| 2 | 왼쪽·오른쪽 중 서브트리 하나만 가짐 | 그 노드를 지우고 서브트리를 부모에 바로 이어 붙인다 |
| 3 | 서브트리 두 개를 모두 가짐 | 삭제 노드와 값이 가장 가까운 노드를 삭제 위치로 끌어 올린다 |

### 4.6 성능 분석

탐색, 삽입, 삭제의 시간 복잡도는 모두 트리 높이 h에 비례한다.

- **최선**: 트리가 균형을 이룬 경우 -> $h = \log_{2}{n}$
- **최악**: 한쪽으로 치우친 경사 트리 -> h = n (순차 탐색과 같아진다)

## 5. AVL 트리

### 5.1 개념

Adelson-Velskii와 Landis가 1962년에 제안한 균형 이진 트리다. 모든 노드에서
왼쪽,오른쪽 서브트리의 높이차를 1 이하로 유지한다. 그래서 평균, 최악 모두
O($\log_{2}{n}$)을 보장한다.

**높이균형 이진 트리**: 빈 트리이거나, 트리 T의 왼쪽, 오른쪽 부속 트리를
T_L, T_R이라 할 때 (1) T_L과 T_R이 모두 높이균형 트리이고, (2) 두 높이차
`|h_L − h_R| <= 1` 을 만족하는 트리.

**균형인자(balance factor)** `BF(T) = h_L − h_R`. AVL 트리의 모든 노드는
BF가 -1, 0, 1 중 하나다. 삽입/삭제로 BF가 +2나 -2가 되면 균형이 깨진
것이므로 회전으로 다시 맞춰야 한다.

### 5.2 4가지 회전

BF가 +-2가 된 노드 A와 새로 삽입된 노드 Y의 위치 관계로 회전 종류가 정해진다.

| 유형 | Y가 삽입된 위치 | 회전 |
|------|----------------|------|
| LL | A의 왼쪽의 왼쪽 부속 트리 | 오른쪽 회전 |
| RR | A의 오른쪽의 오른쪽 부속 트리 | 왼쪽 회전 |
| RL | A의 오른쪽의 왼쪽 부속 트리 | 오른쪽-왼쪽 회전 |
| LR | A의 왼쪽의 오른쪽 부속 트리 | 왼쪽-오른쪽 회전 |

LL과 RR은 서로 대칭, LR과 RL도 서로 대칭이다. RL·LR은 단일 회전 두 번을
조합해 처리한다.

### 5.3 회전 알고리즘

```
rotate_LL(A)
    B의 오른쪽 자식을 A의 왼쪽 자식으로 만든다
    A를 B의 오른쪽 자식 노드로 만든다.

rotate_RR(A)
    B의 왼쪽 자식을 A의 오른쪽 자식으로 만든다
    A를 B의 왼쪽 자식 노드로 만든다.

rotate_RL(A)
    rotate_LL(B)가 반환하는 노드를 A의 오른쪽 자식으로 만든다
    rotate_RR(A)

rotate_LR(A)
    rotate_RR(B)가 반환하는 노드를 A의 왼쪽 자식으로 만든다
    rotate_LL(A)
```

### 5.4 성능, 분석

AVL 트리는 BST가 한쪽으로 치우칠 때 나빠지는 단점을 회전으로 보완해 높이를
$\log n$으로 유지한다. 그래서 검색은 $O(\log n)$이다. 삽입,삭제 시 BF가 +-2가 되는
노드를 회전해 균형을 되돌린다. 검색, 삽입, 삭제의 평균과 최악 모두 $O(\log_{2}n)$이다.

## 6. 2-3 트리

### 6.1 개념

차수가 2 또는 3인 노드로 이루어진 트리다.

- **2-노드**: 이진 탐색 트리처럼 데이터 k1 하나와 자식 노드 2개를 가진다.
- **3-노드**: 데이터 k1, k2 두 개와 자식 노드 3개를 가진다.

3-노드의 대소 관계는 이렇게 나뉜다.

- 왼쪽 서브트리의 값들은 모두 k1보다 작다.
- 가운데 서브트리의 값들은 k1보다 크고 k2보다 작다 (k1 < … < k2).
- 오른쪽 서브트리의 값들은 모두 k2보다 크다.

### 6.2 생성 - 노드 추가와 분리

값은 항상 단말 노드에 추가한다. 노드가 3개의 키를 갖게 되어 넘치면 분리한다.
분리는 세 값 small, middle, large 중 **가운데 값(middle)을 위로 올리고**,
small과 large를 두 자식으로 나누는 방식이다. 분리 위치에 따라 루트 노드
분리, 단말 노드 분리, 비단말 노드 분리로 나뉜다. 단말 노드가 분리될 때는
부모가 2-노드인지 3-노드인지에 따라 middle을 부모에 합치는 모양이 달라진다.

### 6.3 검색 알고리즘

```
tree23_search(Tree23Node *root, int key)
{
    if( root == NULL )               // 트리가 비어 있으면
        return FALSE;
    else if( key == root->key1 )     // 루트의 키 == 탐색 키
        return TRUE;
    else if( root->type == TWO_NODE ) {          // 2-노드
        if( key < root->key1 )
            return tree23_search(root->left, key);
        else
            return tree23_search(root->right, key);
    }
    else {                                       // 3-노드
        if( key < root->key1 )
            return tree23_search(root->left, key);
        else if( key > root->key2 )
            return tree23_search(root->right, key);
        else
            return tree23_search(root->middle, key);
    }
}
```

### 6.4 이진 탐색 트리와 2-3 트리의 비교

데이터 `(30, 20, 40, 15, 25, 10, 35, 50, 45)`를 같은 순서로 넣어 비교하면,
3원 탐색 트리(2-3 트리)가 이진 탐색 트리보다 높이가 낮다. 이진 탐색 트리는
한 단계 내려갈 때 후보가 절반으로 줄지만, 3원 트리는 약 1/3로 줄기 때문이다.

### 6.5 B-트리

m-원 탐색 트리의 성능을 높이려면 m을 크게 하고 트리를 균형 있게 유지한다.
여기에 트리 높이 제한을 두어 탐색을 효율적으로 만든 것이 B-트리다.
B-트리는 다음을 만족하는 m-way 탐색 트리다.

1. 각 노드는 종속 트리를 최대 m개, 최소 ⌈m/2⌉개 가진다.
2. 루트 노드는 최소 두 개의 종속 트리를 가진다.
3. 모든 단말 노드는 같은 레벨(서열)에 있어야 한다.
4. 노드의 키 개수는 종속 트리 개수보다 하나 적으며, 최소 ⌈m/2⌉-1개,
   최대 m-1개다.

### 6.6 B+트리

B-트리는 한 데이터 검색은 효율적이지만, 모든 데이터를 한 번 순회하려면
모든 노드를 방문해야 해 비효율적이다. 이를 개선한 것이 B+트리다.

- 데이터는 오직 leaf node에만 저장하고, leaf가 아닌 노드에는 자식 포인터만
  둔다.
- leaf node끼리는 연결 리스트(linked list)로 이어져 있어 전체 순회가 빠르다.

## 연습문제 풀이

### AVL 트리 생성

**입력데이터**: `( 23, 38, 74, 27, 48, 39, 42, 15, 18, 14, 17, 13 )`

각 값을 순서대로 삽입하며, BF가 ±2가 되는 노드가 생기면 회전으로 균형을
맞춘다. 강의 슬라이드의 단계별 트리를 따라간 풀이는 다음과 같다.

1. **23 삽입** - 루트 `23`(BF 0). 균형.
2. **38 삽입** - 23의 오른쪽에 `38`. 23의 BF가 -1. 균형.
3. **74 삽입** - 38의 오른쪽에 `74`. 23의 BF가 -2(비균형, RR 형태)
   -> **RR 회전**. 결과: 루트 `38`, 왼쪽 `23`, 오른쪽 `74` (모두 BF 0).
4. **27 삽입** - 23의 오른쪽에 `27`. 균형 유지 (38의 BF -1).
5. **48 삽입** - 74의 왼쪽에 `48`. 균형 유지.
6. **39 삽입** - 48의 왼쪽에 `39`. 74의 BF가 -2(비균형, LL 형태)
   -> **LL 회전**. 74 자리를 48이 대신하고, 48의 왼쪽 `39`, 오른쪽 `74`.
   결과 루트는 `38`, 오른쪽 서브트리 루트가 `48`.
7. **42 삽입** - 39의 오른쪽에 `42`. 균형 유지.
8. **15 삽입** - 23의 왼쪽에 `15`. 균형 유지.
9. **18 삽입** - 15의 오른쪽에 `18`. 균형 유지.
10. **14 삽입** - 15의 왼쪽에 `14`. 균형 유지.
11. **17 삽입** - 14·18 부근에 삽입되며 23의 BF가 -2(비균형, LR 형태)
    -> **LR 회전**. 18이 올라와 왼쪽 서브트리 루트가 되고, 아래로 15와 23이
    나뉜다. (강의 11) LR회전 그림)
12. **13 삽입** - 14의 왼쪽에 `13`. 최종 균형 트리 완성.

최종 트리는 루트 `38`(BF -1), 왼쪽 서브트리 루트 `18`, 오른쪽 서브트리 루트
`48` 형태이며 모든 노드의 BF가 -1, 0, 1 범위 안에 든다.

> 이 풀이의 각 회전(RR, LL, LR)은 [5.2 4가지 회전](#52-4가지-회전)의
> 판정 규칙(A와 Y의 위치 관계)을 그대로 적용한 것이다.
