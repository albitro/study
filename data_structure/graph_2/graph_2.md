## 핵심 요약

- **신장트리(spanning tree)**: 원래 그래프의 정점을 모두 포함하면서, 간선을 n − 1개만 골라 사이클 없이 전체를 연결한 부분 그래프. DFS로 만들면 깊이우선 신장트리, BFS로 만들면 너비우선 신장트리다.
- **최소신장트리(MST)**: 간선에 비용이 있을 때, 비용 합이 가장 작은 신장트리. **Kruskal**(간선을 싼 것부터 고르되 사이클 만들면 버림)과 **Prim**(한 정점에서 출발해 이어진 간선 중 가장 싼 것으로 확장)으로 구한다.
- **최단 경로(shortest path)**: 출발점에서 각 정점까지 비용 합이 최소인 경로. **Dijkstra 알고리즘**은 아직 확정 안 된 정점 중 distance가 가장 작은 것을 하나씩 확정해 나가며, 그 정점을 거쳐 가는 길로 나머지 distance를 갱신한다.
- **추이적 폐쇄(transitive closure)**: 어떤 정점에서 다른 정점으로 (직접이든 여러 단계를 거치든) 갈 수 있는가를 표로 정리한 것. 인접 행렬로부터 계산한다.

## 4. 신장트리, 최소신장트리

### 4.1 신장트리의 정의

그래프 G의 신장트리 G′는 G의 부분 그래프이면서 다음을 모두 만족한다.

- **V(G′) = V(G)** - 정점은 원래 그래프와 완전히 같다
- **G′ is connected** - 전체가 하나로 연결되어 있다
- **|E(G′)| = n − 1** - 간선 수가 정점 수보다 정확히 1개 적다

정점은 그대로 두고 간선만 (노드 수 − 1)개로 줄여, 전체가 연결된 상태를 유지하는 그래프다. 간선이 정점보다 1개 적으면 사이클이 생길 수 없으므로, 신장트리에는 사이클이 없다.

실제 문제로 옮기면 이해가 쉽다.

- 도시 10곳에 송유관을 놓을 때, 중복(사이클) 없이 9개의 송유관으로 모든 도시를 원유 공급지와 잇는 문제가 신장트리 문제다.
- 건물들의 컴퓨터 네트워크를 연결할 때, 사이클 없이 모든 건물이 이어지도록 통신선을 구성하는 문제도 마찬가지다.

### 4.2 신장트리의 생성

정점 수가 n인 그래프에서, 모든 정점이 연결되도록 간선 n − 1개를 고르면 신장트리가 된다. 그래프가 작고 그림으로 그려져 있으면 눈으로 고를 수 있지만, 그래프가 크고 인접 행렬이나 인접 리스트로만 표현돼 있으면 프로그램으로 간선을 골라야 한다. 이때 앞 장에서 배운 **DFS**나 **BFS**를 쓰면 쉽게 해결된다.

두 탐색은 그래프를 훑으며 간선을 따라 이동하는데, 마주치는 간선은 두 종류로 나뉜다.


| 간선 종류                     | 의미                                                 |
| ------------------------------- | ------------------------------------------------------ |
| 트리 에지 T (tree edges)      | 탐색 도중 실제로 타고 넘어가 방문에 쓰인 간선의 집합 |
| 비트리 에지 N (nontree edges) | 나머지 간선들. 이미 방문한 노드를 확인만 하는 간선   |

T에 속한 간선만 그리면 G의 모든 노드를 포함하는 트리가 만들어진다. 이렇게 얻은 그래프는 정점을 모두 연결하면서 간선 수를 최소로 하는 방법이다.

### 4.3 신장트리의 종류

하나의 그래프에서 나올 수 있는 신장트리는 여러 개다. 어떤 탐색으로 간선을 골랐는지에 따라 이름이 갈린다.

- **깊이우선 신장트리 (depth first spanning tree)**: DFS로 방문한 간선으로 만든 신장트리
- **너비우선 신장트리 (breadth first spanning tree)**: BFS로 방문한 간선으로 만든 신장트리

**신장트리의 성질**: 신장트리에 새 간선(nontree edge) (v, w)를 하나 더하면 사이클이 생긴다.

### 4.4 최소신장트리의 정의

간선에 비용(cost, 거리)이 붙어 있으면, 단순히 n − 1개를 고르는 데서 나아가 **비용 합이 최소가 되도록** 고르고 싶어진다. 이렇게 간선 비용의 총합을 최소로 만드는 신장트리가 **최소신장트리(minimum cost spanning tree, MST)**다.

MST는 대표적으로 **Kruskal**과 **Prim** 두 알고리즘으로 구한다.

### 4.5 Kruskal 알고리즘

**아이디어.** 노드만 그려 둔 빈 그래프에, 비용이 가장 작은 간선부터 하나씩 더해 나간다. 가장 싼 간선만 고르므로 최종으로 뽑힌 n − 1개 간선의 비용 합은 최소가 된다. 단, 간선을 더할 때 **사이클을 만드는 간선은 자격이 없으므로 버린다.**

```
T = {};                     /* T에 구해진 에지를 더한다 */
while(T contains less than n-1 edges && E is not empty) {
    choose a least cost edge (v,w) from E;   /*1*/
    delete (v,w) from E;
    if((v,w) does not create a cycle in T)   /*2*/
        add(v,w) to T;
    else  discard (v,w);
}
if(T contains fewer than n-1 edges)
    printf("no spanning tree\n");
```

**수행 예시** (강의 그래프 G, 정점 0~6):


| 에지  | 비용 | 결과              |
| ------- | ------ | ------------------- |
| (0,5) | 10   | 선택              |
| (2,3) | 12   | 선택              |
| (1,6) | 14   | 선택              |
| (1,2) | 16   | 선택              |
| (3,6) | 18   | 버림 (사이클)     |
| (3,4) | 22   | 선택              |
| (4,6) | 24   | 버림 (사이클)     |
| (4,5) | 25   | 선택              |
| (0,1) | 28   | 더 이상 필요 없음 |

싼 간선부터 훑으며, 사이클을 만드는 (3,6)과 (4,6)은 건너뛴다. 간선 6개(= n − 1 = 7 − 1)를 고르면 모든 정점이 연결되어 종료한다.

### 4.6 Prim 알고리즘

**아이디어.** 한 노드에서 출발해 연결된 부속 그래프를 키워 나간다. 이미 트리에 들어온 정점 집합(TV)에서, TV 안의 정점과 TV 밖의 정점을 잇는 간선 중 **비용이 가장 작은 것**을 골라, 그 바깥 정점을 트리에 새로 넣는다.

```
T = {};                     /* 초기에 빈 노드의 그래프 */
TV = {0};                   /* 노드번호 0번에서 시작한다 */
while(T contains fewer than n-1 edges) {
    let (u,v) be a least cost edge
        such that u ∈ TV and v ∉ TV;
    if(there is no such edge) break;
    add v to TV;
    add (u,v) to T;
}
if(T contains fewer than n-1 edges)
    printf("no spanning tree\n");
```

**수행 예시** (강의 그래프 G, 0번에서 시작). TV가 커지는 과정:


| 단계 | 추가한 간선 | TV                    |
| ------ | ------------- | ----------------------- |
| a    | (0,5) 포함  | {0, 5}                |
| b    | (5,4) 포함  | {0, 5, 4}             |
| c    | (4,3) 포함  | {0, 5, 4, 3}          |
| d    | (3,2) 포함  | {0, 5, 4, 3, 2}       |
| e    | (2,1) 포함  | {0, 5, 4, 3, 2, 1}    |
| f    | (1,6) 포함  | {0, 5, 4, 3, 2, 1, 6} |

Kruskal이 "간선 전체에서 싼 것"을 고르는 반면, Prim은 "지금까지 만든 트리에 붙는 간선 중 싼 것"을 고른다는 점이 다르다.

## 5. 최단 경로

### 5.1 최단 경로의 정의

지하철에서 종로1가 -> 강남역으로 갈 때, 갈아타더라도 가장 빨리(시간) 가거나, 가장 짧은 거리로 가거나, 지나는 역 수를 가장 적게 거치는 방법을 찾는 문제가 최단 경로 문제다.

경로의 길이는 경로 위 간선에 붙은 비용의 합이다. 비용은 거리나 시간일 수 있다. 만약 지나는 역 수만 따진다면, 역 사이 거리 값을 모두 1로 두고 계산하면 된다.

예제 그래프에서 v0에서 각 정점까지의 최단 거리:


| 경로        | 길이 합 |
| ------------- | --------- |
| v0 v2       | 10      |
| v0 v2 v3    | 25      |
| v0 v2 v3 v1 | 45      |
| v0 v4       | 45      |

### 5.2 최단 경로 구하기

최단 경로 문제는 한 정점 v0에서 특정 정점 w까지를 구하는 문제처럼 보이지만, 구하는 과정에서 출발점 v0로부터 **모든 도착점까지 한꺼번에** 구하게 된다. 즉 모든 정점 w에 대해 `distance[w]`를 구한다.

- **집합 S**: 이미 최단 경로가 확정된 정점들의 모임. S에 든 정점은 계산이 끝난 정점이다.
- **distance[w]**: 알고리즘 시작 시엔 출발점에서 w로 바로(인접해서) 가는 거리다. 진행 중에는 출발점에서 w까지의 최단 거리 값이 되며, w가 S에 들어가면 그 값이 최종값으로 확정된다. 아직 S 밖이면, 출발점에서 S를 거쳐 가는 경로 중 가장 짧은 값을 담는다.

**새 정점을 S에 넣을 때**: S 밖의 정점 중 `distance[u]`가 가장 작은 정점 u를 고른다. 그러고 나면, S 밖의 각 정점 w에 대해 distance[w]를 다음 두 값 중 작은 쪽으로 갱신한다.

1. S만 거쳐 가는 기존 거리 (이미 계산됨): `distance[w]`
2. 방금 확정된 u를 거쳐 가는 거리: `distance[u] + length(⟨u, w⟩)`

즉 갱신 규칙은

```
distance[w] = min( distance[w], distance[u] + cost[u][w] )
```

이다. u는 이미 최단 경로가 확정된 정점이므로, u를 거쳐 w로 가는 길과 기존 값만 비교하면 충분하고 다른 더 짧은 경로는 없다.

### 5.3 Dijkstra 알고리즘

위 아이디어를 그대로 옮긴 것이 Dijkstra 알고리즘이다.

```
#define MAX_VERTICES 6
int cost[][MAX_VERTICES] =
    {{   0,  50,  10,1000,  45,1000},
     {1000,   0,  15,1000,  10,1000},
     {  20,1000,   0,  15,1000,1000},
     {1000,  20,1000,   0,  35,1000},
     {1000,1000,  30,1000,   0,1000},
     {1000,1000,1000,   3,1000,   0}};
int distance[MAX_VERTICES];
short int found[MAX_VERTICES];
int n = MAX_VERTICES;
```

여기서 1000은 "간선이 없음(도달 불가)"을 나타내는 큰 값이다.

```
void shortestpath(int v, int cost[][MAX_VERTICES],
                  int distance[], int n, short int found[]) {
    int i, u, w;
    for(i = 0; i < n; i++) {          /* 초기화 */
        found[i] = FALSE;
        distance[i] = cost[v][i];
    }
    found[v] = TRUE;
    distance[v] = 0;
    for(i = 0; i < n-2; i++) {
        u = choose(distance, n, found);       /*1*/
        found[u] = TRUE;
        for(w = 0; w < n; w++)
            if(!found[w])                     /*2*/
                if(distance[u]+cost[u][w] < distance[w])
                    distance[w] = distance[u]+cost[u][w];
    }
}
```

choose 함수: 아직 확정 안 된(`!found[i]`) 정점 중 distance가 가장 작은 정점의 위치를 반환한다.

```
int choose(int distance[], int n, int found[]) {
    int i, min, minpos;
    min = INT_MAX;
    minpos = -1;
    for(i = 0; i < n; i++)
        if(distance[i] < min && !found[i]) {
            min = distance[i];
            minpos = i;
        }
    return minpos;
}
```

**Boston 예제** Boston(정점 4)에서 각 도시까지의 최단 거리를 Dijkstra로 구하는 과정을 반복별로 정리하면 다음과 같다. $+\inf$는 아직 도달 못 함을 뜻한다.


| Iteration | S             | 선택 정점 | LA[0]   | SF[1]   | DEN[2]  | CHI[3] | BOST[4] | NY[5] | MIA[6]  | NO[7]   |
| ----------- | --------------- | ----------- | --------- | --------- | --------- | -------- | --------- | ------- | --------- | --------- |
| Initial   | --            | --        | $+\inf$ | $+\inf$ | $+\inf$ | 1500   | 0       | 250   | $+\inf$ | $+\inf$ |
| 1         | {4}           | 5         | $+\inf$ | $+\inf$ | $+\inf$ | 1250   | 0       | 250   | 1150    | 1650    |
| 2         | {4,5}         | 6         | $+\inf$ | $+\inf$ | $+\inf$ | 1250   | 0       | 250   | 1150    | 1650    |
| 3         | {4,5,6}       | 3         | $+\inf$ | $+\inf$ | 2450    | 1250   | 0       | 250   | 1150    | 1650    |
| 4         | {4,5,6,3}     | 7         | 3350    | $+\inf$ | 2450    | 1250   | 0       | 250   | 1150    | 1650    |
| 5         | {4,5,6,3,7}   | 2         | 3350    | 3250    | 2450    | 1250   | 0       | 250   | 1150    | 1650    |
| 6         | {4,5,6,3,7,2} | 1         | 3350    | 3250    | 2450    | 1250   | 0       | 250   | 1150    | 1650    |

매 반복마다 S 밖에서 distance가 가장 작은 정점을 S에 넣고, 그 정점을 거쳐 가는 길로 나머지를 갱신하는 것이 핵심이다.

## 6. 추이적 폐쇄

### 6.1 추이적 관계

집합 X 위의 관계 R이 **추이적(transitive)** 이라는 것은, X의 원소 a, b, c에 대해 `aRb`이고 `bRc`이면 `aRc`도 성립한다는 뜻이다. 예를 들어 "크다", "크거나 같다", "같다"는 모두 추이적 관계다.

추이적 관계에서 관계 R이 이항관계인 경우를 **추이적 폐쇄(transitive closure)** 라고 한다. 활용처는 다음과 같다.

- 분산 시스템/병렬 시스템을 나타내는 전이 네트워크의 **도달 가능성 분석(reachability analysis)**
- 컴파일러 구성에서 파싱 오토마타를 구성할 때

### 6.2 추이적 폐쇄 행렬

그래프에서 노드 x에서 노드 y로 가는 경로가 있는지를 묻는 문제다. (최단 경로 문제는 여기서 더 나아가 경로의 비용까지 구했다.) 그래프를 행렬로 나타내면, x에서 y로 **바로** 가는 간선이 있으면 1, 없으면 0을 저장한다. 그런데 경로는 직접 간선뿐 아니라, 여러 정점을 거쳐 가는 간접 경로도 포함해서 찾아야 한다.

이를 수학적으로 정리한 것이 **추이적 폐쇄 행렬 $A^+$** 다.

- 노드 i에서 j로 가는 경로(길이 > 0)가 있으면 `A⁺[i][j] = 1`
- 그렇지 않으면 `A⁺[i][j] = 0`

인접 행렬 $A$로부터 $A^+$를 구하는 방법은 행렬을 곱해 나가는 것이다.

**예시.** 방향 그래프 (a->b, b->d, d->a, d->c)의 인접 행렬 $A$와, 여기서 계산한 추이적 폐쇄 $T$:

```
     a b c d              a b c d
  a  0 1 0 0           a  1 1 1 1
A=b  0 0 0 1        T= b  1 1 1 1
  c  0 0 0 0           c  0 0 0 0
  d  1 0 1 0           d  1 1 1 1
```

예를 들어 a는 b로 직접 갈 수 있고, b->d->a->… 를 거쳐 c까지도 도달할 수 있으므로 $T$의 a행이 모두 1이 된다. 반면 c에서는 나가는 간선이 없어 아무 데도 못 가므로 c행은 모두 0이다.

### 문제 1. Kruskal과 Prim으로 MST 구하기

정점 A~H, 간선과 비용:
A-D 3, A-B 6, A-E 8, D-E 2, B-E 6, B-C 4, B-F 3, B-H 4, E-F 6, E-G 5, E-H 2, C-F 3, F-H 5, G-H 2.

**Kruskal** - 비용이 작은 간선부터 고르고, 사이클을 만들면 버린다.


| 순서 | 간선 | 비용 | 결과                               |
| ------ | ------ | ------ | ------------------------------------ |
| 1    | D-E  | 2    | 선택 {D,E}                         |
| 2    | E-H  | 2    | 선택 {D,E,H}                       |
| 3    | G-H  | 2    | 선택 {D,E,H,G}                     |
| 4    | A-D  | 3    | 선택 {A,D,E,H,G}                   |
| 5    | B-F  | 3    | 선택 {B,F} (별도 묶음)             |
| 6    | C-F  | 3    | 선택 {B,C,F}                       |
| 7    | B-C  | 4    | 버림 (B,C 이미 연결 -> 사이클)     |
| 8    | B-H  | 4    | 선택 -> 두 묶음이 합쳐져 전부 연결 |

간선 7개(= 8 − 1)를 골랐고 모든 정점이 연결되어 종료.

```
MST 간선: D-E, E-H, G-H, A-D, B-F, C-F, B-H
총 비용 : 2 + 2 + 2 + 3 + 3 + 3 + 4 = 19
```

**Prim** - A에서 출발해, 트리에 붙는 간선 중 가장 싼 것으로 확장한다.


| 단계 | 추가 간선 | 비용 | TV                |
| ------ | ----------- | ------ | ------------------- |
| 1    | A-D       | 3    | {A,D}             |
| 2    | D-E       | 2    | {A,D,E}           |
| 3    | E-H       | 2    | {A,D,E,H}         |
| 4    | H-G       | 2    | {A,D,E,H,G}       |
| 5    | H-B       | 4    | {A,D,E,H,G,B}     |
| 6    | B-F       | 3    | {A,D,E,H,G,B,F}   |
| 7    | F-C       | 3    | {A,D,E,H,G,B,F,C} |

```
총 비용 : 3 + 2 + 2 + 2 + 4 + 3 + 3 = 19
```

> 두 알고리즘 모두 총 비용 **19**로 같다. MST의 총 비용은 어떤 방법으로 구하든 동일하다.
